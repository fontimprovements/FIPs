# FIP001 — Path boolean subtraction

A closed path marked as a **subtraction cutter** punches a hole in
everything **below** it in the layer’s shape list. Paths and components share
that list: their relative order is the stacking order. The cutter itself is
omitted from the compiled outline.

Editors keep the original nodes. Compilers flatten, difference, and export
only the remaining additive contours.

## Motivation

Designers often need a hole that stays editable: an accent that cuts a bowl,
or a halo around a mark, without destructive booleaning or reverse-winding
tricks. Those approaches lose the cutter as an object, and they do not say
how a cutter on a **component** should interact with paths on the **host**.

This FIP stores a flag on the cutter path and defines one stacking rule so
editors and compilers agree.

## Intended use

This is aimed at **single-weight** fonts.

Compile decomposes any glyph whose own paths **or** component tree contain a
cutter, then flattens those outlines. That is a poor fit for variable fonts:
it drops component sharing, and it can introduce outline incompatibility —
including from self-overlaps that interpolated cleanly while they stayed
inside a component, then vanish or change after flatten. It can still work on
a VF in limited cases, if applied sparingly and checked on every master.

Glyphs with no cutter in their tree keep their components.

## Storage

On each cutter **path** (not on the glyph, not on the font):

| Key | Value |
| --- | --- |
| `fip001-boolean` | `"subtraction"` |

Other values are reserved. No key means an ordinary additive path.

Round-trip the key on the path object:

- **Glyphs** (`.glyphs` / `.glyphspackage`): path `attr["fip001-boolean"] =
  subtraction`. Intermediate models may also keep
  `format_specific["fip001-boolean"]`.
- **UFO / Designspace, Babelfont JSON, FontLab VFJ**, and similar: the same
  key on the path’s custom / format-specific dictionary.

The flag is per path, per layer. Matching interpolating layers should carry
the same flag at the same shape indexes. Background layers need not be
processed.

## Stacking

A layer is one ordered list of shapes (paths and components mixed). That list
is the z-order:

- **Earlier** = below (subject to later cutters).
- **Later** = above (covers holes left by earlier cutters).

Paths and components are not two stacks. A component between two paths sits
between those paths. Reordering shapes changes the boolean result.

Compile sees paths only. Before subtraction it:

1. Finds every glyph whose own paths or **component tree** contain at least
   one subtraction path.
2. **Decomposes** those glyphs so each component is replaced **in place** by
   the referenced glyph’s shapes, with the component transform applied.
   Nested components expand the same way.
3. Walks the flat closed-path list bottom to top:
   - Additive closed paths accumulate as the subject.
   - A **closed** cutter replaces that subject with NonZero **difference**
     (`subject − cutter`) and is not kept.
   - Additive paths **after** that cutter sit on the hole.
   - Open paths are never cutters.

A cutter that lived inside a component only cuts what appears **before** it
after flatten: earlier paths of that component, plus earlier sibling shapes of
the host. Host shapes listed **after** that component are not cut.

Fill rule: **NonZero**. The compiled font does not store `fip001-boolean`.

## Example

`O` is the base. `Odieresis` is `O` plus two `dotaccentcomb` components.
Each `dotaccentcomb` has a **dot** and an extra closed path marked subtraction.
Those punches cut a halo out of `O` around each dot. The dots stay on top, so
they are not eaten.

After flatten, order is `O`, then (per mark) the punch, then the dot. If a
punch were last in `dotaccentcomb`, it would cut its own dot.

## Preview

Live preview should match compiled coverage: additive fill only where the
binary has ink; a cutter above a solid punches that solid; an additive above
a cutter covers the hole.

## Out of scope

Intersection / clip (a later value of `fip001-boolean` could define that).
How overlapping additive paths combine when there is no cutter. Hinting and
UI.

## Notes

Geometry can use a robust path boolean (for example Linesweeper
`binary_op` with `FillRule::NonZero` and `BinaryOp::Difference`). Editors may
approximate the same coverage on canvas without rewriting source nodes.

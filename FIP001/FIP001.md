# FIP001 — Path boolean subtraction

A closed path marked **subtraction** punches a hole in everything **below**
it in the layer’s shape list. Paths and components share that list. The cutter
is omitted from the compiled outline.

This is aimed at **single-weight** fonts. Compile decomposes any glyph whose
own paths or component tree contain a cutter, then flattens those outlines.
That is a poor fit for variable fonts: it drops component sharing, and it
can introduce outline incompatibility (including from self-overlaps that
were fine while they stayed inside a component, then vanish or change after
flatten). It can still work on a VF if used sparingly and checked per master.

## Storage

On the cutter **path**:

| Key | Value |
| --- | --- |
| `fip001-boolean` | `"subtraction"` |

Anything else is reserved. No key means an ordinary additive path.

Round-trip it on the path (Glyphs: path `attr`; UFO / Babelfont / VFJ: the
path’s custom / format-specific dict). Per path, per layer. Background layers
need not be processed.

## Stacking

A layer is one ordered shape list (paths and components mixed). Earlier = below;
later = above. Reordering shapes changes the holes.

Compile flattens components **in place** (transform applied, nested the same
way) on glyphs that need this filter, then walks the flat path list bottom to
top:

1. Additive closed paths accumulate.
2. A closed cutter replaces that subject with NonZero **difference**
   (`subject − cutter`) and is not kept.
3. Additive paths after the cutter sit on the hole.
4. Open paths are never cutters.

A cutter inside a component only cuts what appears **before** it after
flatten (earlier paths in that component, plus earlier shapes on the host).
Host shapes listed **after** that component are not cut.

## Example

`O` is the base. `Odieresis` is `O` plus component `dieresiscomb`.
`dieresiscomb` has two **dot components** and two extra closed paths marked
subtraction. Those punches cut a halo out of `O` around each dot. The dots
stay on top, so they are not eaten.

After flatten, order is `O`, then the punches, then the dot components
(punches before dots inside `dieresiscomb`). If the punches were last, they
would cut the dots too.

## Out of scope

Intersection / clip. Additive overlap without a cutter. Hinting and UI.

## Notes

Geometry: NonZero difference (e.g. Linesweeper). Editors can preview without
rewriting source nodes. The binary does not store the flag.
